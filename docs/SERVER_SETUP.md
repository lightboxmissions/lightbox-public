# Setting up a Lunis server


This is the full recipe for standing up a Lunis box from scratch: the web app, the
local AI model, the translation engine, and the auto‑start service. It targets **Ubuntu
Linux** (the reference box is a laptop running Ubuntu with 4 CPU cores, ~7 GB RAM, **no
GPU**), but any Linux with Python 3.9+ works. Everything runs **offline** once set up.

If you only want to *edit the code*, you don't need this — see
[WINDOWS_SETUP.md](WINDOWS_SETUP.md). Come here when you're building a new box, moving
to new hardware, or you need to understand/repair the running one.

> **Run your own server.** This sets up a **complete, independent** Lunis box that you
> own — it does not connect to or depend on anyone else's server.

---

## The easy way — one command

On a fresh **Ubuntu** machine (with internet for the install), run:

```bash
sudo apt-get update && sudo apt-get install -y git
git clone https://github.com/lightboxmissions/Lunis.git ~/lightbox
cd ~/lightbox
bash server/install.sh
```

`server/install.sh` does the entire setup below for you:

- installs Python, Git, build tools, **llama.cpp**, and **LibreTranslate**;
- downloads the **Qwen2.5‑3B** model (~1.9 GB, one time);
- builds the lesson transcripts;
- creates three auto‑restart services — **`lightbox`** (the app, port 8090),
  **`lightbox-llama`** (the AI, 8080), **`lightbox-translate`** (translation, 5000) —
  and enables them to start on boot;
- health‑checks the app and prints the URL to open.

It's safe to re‑run (it skips whatever's already done). When it finishes, open
`http://<your-box-ip>:8090`, complete the one‑time teacher‑password wizard, and you're
live. The first AI answer and the first translator start take about a minute to warm up.

**Manage it afterwards:**

```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
systemctl --user status lightbox lightbox-llama lightbox-translate
systemctl --user restart lightbox
journalctl --user -u lightbox -n 50
```

The rest of this document explains each piece **by hand** — read it if the installer
hits a snag, you're on a non‑Debian distro, or you want to understand what's running.
(The manual steps below use the older `~/lightbox` path and `khan-tutor` service name as an
example; the installer uses `~/lightbox` and the `lightbox*` names shown above.)

## The three pieces

Lunis is one small Python web app that talks to two local helper services:

```
                          ┌─────────────────────────────┐
   student browser  ─────▶│  Lunis web app (Python)  │  port 8090
                          │       app/server.py         │
                          └───────┬──────────────┬──────┘
                                  │              │
                     AI answers   │              │  translations
                                  ▼              ▼
                      ┌───────────────┐   ┌───────────────────┐
                      │  llama.cpp    │   │  LibreTranslate   │
                      │  (Qwen2.5-3B) │   │  en/fr/es/de      │
                      │   port 8080   │   │    port 5000      │
                      └───────────────┘   └───────────────────┘
```

The Python app itself needs **no dependencies** (standard library only). The two helper
services are independent programs you install once.

## Folder layout on the box

The reference box keeps everything under `~/lightbox`. **The app folder must be named
`app`** and sit one level under the project root, because the code finds `data/`,
`content/`, and `transcripts/` as siblings of `app/`:

```
~/lightbox/
├─ app/            ← this repo's app/ folder (server.py, static/, prep.py, ...)
├─ data/           ← this repo's data/ folder (catalog/notes/quizzes + runtime files)
├─ content/        ← the videos + captions  (<CODE>.mp4 / <CODE>.srt)
├─ transcripts/    ← generated by app/prep.py
├─ config.json     ← operator config (copied from config.example.json)
└─ restart.sh      ← copied from deploy/restart.sh (used by the deploy script)
```

## 1. Install Python and get the code

```bash
sudo apt update
sudo apt install -y python3 git curl

git clone https://github.com/lightboxmissions/Lunis.git ~/lightbox
# (or clone elsewhere and copy app/ and data/ into ~/lightbox)

cp ~/lightbox/deploy/restart.sh ~/lightbox/restart.sh
chmod +x ~/lightbox/restart.sh
cp ~/lightbox/config.example.json ~/lightbox/config.json   # edit if your ports differ
```

At this point you can already start the web app (`python3 ~/lightbox/app/server.py`) and
load it in a browser — the AI and translation just won't answer yet.

## 2. Add the video content

**If you cloned this repo, the 67 grade K–3 videos + captions are already in
`content/` and the transcripts in `transcripts/` — you can skip this step.** It only
applies when you're populating a box from a bare/partial checkout or adding new media.

Copy the flat `content/<CODE>.mp4` + `<CODE>.srt` files into `~/lightbox/content/`.

- **From an existing archive of the original downloads**, run the helper on that machine
  first (see [`content/README.md`](../content/README.md)) and copy the resulting
  `content/` folder over, e.g.:
  ```bash
  scp -r content/  user@box:~/lightbox/content/
  ```
- Then build the plain‑text transcripts the AI reads from the captions:
  ```bash
  cd ~/lightbox && python3 app/prep.py
  ```
  This writes `~/lightbox/transcripts/<CODE>.txt` for every lesson in the catalog.

## 3. Install the AI model (llama.cpp)

Lunis talks to any OpenAI‑compatible chat endpoint. The reference box uses
[llama.cpp](https://github.com/ggml-org/llama.cpp)'s `llama-server` with
**Qwen2.5‑3B‑Instruct (Q4_K_M)** — small enough to run on CPU at a few tokens/sec.

```bash
# build llama.cpp (needs build-essential + cmake)
sudo apt install -y build-essential cmake
git clone https://github.com/ggml-org/llama.cpp ~/llama.cpp
cmake -S ~/llama.cpp -B ~/llama.cpp/build
cmake --build ~/llama.cpp/build -j --config Release
```

Download the model (a ~2 GB GGUF file). On a machine with internet, grab
`qwen2.5-3b-instruct-q4_k_m.gguf` from the Qwen GGUF repo on Hugging Face
(e.g. `Qwen/Qwen2.5-3B-Instruct-GGUF`), and place it at `~/models/`.

Start the model server (bind to localhost — only the app needs it):

```bash
~/llama.cpp/build/bin/llama-server \
  -m ~/models/qwen2.5-3b-instruct-q4_k_m.gguf \
  --host 127.0.0.1 --port 8080 \
  -c 4096 -t 4                       # 4 CPU threads to match the box
```

Verify:

```bash
curl -s http://127.0.0.1:8080/v1/models
```

> The model **name** Lunis sends is set by `model` in `config.json`. llama.cpp
> accepts any name, so leaving the default is fine.

## 4. Install translation (LibreTranslate)

[LibreTranslate](https://github.com/LibreTranslate/LibreTranslate) is a self‑hosted
translation API. Install it in its own Python virtualenv so it can't clash with the
system Python the app uses:

```bash
sudo apt install -y python3-venv
python3 -m venv ~/libretranslate-venv
~/libretranslate-venv/bin/pip install libretranslate

~/libretranslate-venv/bin/libretranslate \
  --host 127.0.0.1 --port 5000 \
  --load-only en,fr,es,de           # the 4 languages Lunis supports
```

The first launch downloads the language models (needs internet once); after that it's
fully offline. Verify:

```bash
curl -s http://127.0.0.1:5000/languages
```

> **Important content rule already handled in code:** LibreTranslate mangles bare math
> like `1/2`, so `server.py` deliberately skips translating any string that has no
> 2‑letter word. Don't "fix" that.

## 5. Point the app at the two services

Edit `~/lightbox/config.json` (copied from `config.example.json`) if anything differs from
the defaults:

```json
{
  "host": "0.0.0.0",
  "port": 8090,
  "llama_url": "http://127.0.0.1:8080/v1/chat/completions",
  "model": "qwen2.5-3b-instruct-q4_k_m.gguf",
  "libretranslate_url": "http://127.0.0.1:5000/translate"
}
```

`host: 0.0.0.0` makes the app reachable from student devices on the LAN/hotspot. Any of
these can also be overridden with an env var like `LIGHTBOX_PORT=9000`.

## 6. Run everything automatically on boot (systemd)

You want all three services to start on boot and restart if they crash. The reference
box runs them as **user** services with *linger* enabled (so they start at boot without
anyone logging in). Create three unit files under `~/.config/systemd/user/`:

**`~/.config/systemd/user/khan-tutor.service`** (the web app):

```ini
[Unit]
Description=Lunis math tutor web app
After=network.target

[Service]
Type=simple
WorkingDirectory=%h/khan/app
ExecStart=/usr/bin/python3 %h/khan/app/server.py
Restart=always
RestartSec=3

[Install]
WantedBy=default.target
```

**`~/.config/systemd/user/llama.service`** (adjust the paths to yours):

```ini
[Unit]
Description=llama.cpp server (Qwen2.5-3B) for Lunis
After=network.target

[Service]
Type=simple
ExecStart=%h/llama.cpp/build/bin/llama-server -m %h/models/qwen2.5-3b-instruct-q4_k_m.gguf --host 127.0.0.1 --port 8080 -c 4096 -t 4
Restart=always
RestartSec=5

[Install]
WantedBy=default.target
```

**`~/.config/systemd/user/libretranslate.service`**:

```ini
[Unit]
Description=LibreTranslate for Lunis
After=network.target

[Service]
Type=simple
ExecStart=%h/libretranslate-venv/bin/libretranslate --host 127.0.0.1 --port 5000 --load-only en,fr,es,de
Restart=always
RestartSec=5

[Install]
WantedBy=default.target
```

Enable them:

```bash
loginctl enable-linger "$USER"          # start user services at boot, no login needed
systemctl --user daemon-reload
systemctl --user enable --now llama libretranslate khan-tutor
```

Check status (note: **user** services don't show in the system `systemctl list-units`):

```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)   # needed when you're over SSH
systemctl --user status khan-tutor
journalctl --user -u khan-tutor -n 50       # recent app logs
```

The included **`deploy/restart.sh`** is the safe way to restart just the web app after
a code deploy — it stops the service, kills any stray `server.py` holding port 8090,
clears the failed state, starts it again, and health‑checks HTTP 200.

## 7. First‑run setup wizard

Open the app in a browser (`http://<box-ip>:8090`). The **first time**, it shows a
one‑time welcome wizard where an adult sets:

- a **teacher/admin password** (until then the default access code is `lightbox`), and
- the **default language**.

That choice is saved to `data/setup.json`. After that, students just sign in with their
name. Per‑student quiz results land in `data/progress/<name>.json`.

## 8. Let students connect (Wi‑Fi hotspot)

For a room with no internet, the box broadcasts its own Wi‑Fi:

- Turn on the hotspot (the reference box uses a small script, `~/hotspot-on.sh`, that
  brings up an access point named **`lightbox`**). On modern Ubuntu you can also create
  a hotspot from *Settings → Wi‑Fi → ⋮ → Turn On Wi‑Fi Hotspot*, or with
  `nmcli device wifi hotspot ssid lunis password <pass>`.
- Students join the **`lightbox`** network, then open **`http://<box-ip>:8090`**.
- The box's IP depends on the network: on its own hotspot it is the box's hotspot
  address; on an existing Wi‑Fi it is whatever the router gave it. Find it with
  `ip addr` or `hostname -I`.

Nothing is installed on student devices — they only stream from the box.

## Adding a new lesson (content workflow)

Lessons are defined by data files plus a matching video/caption pair. To add one:

1. Put the media at `content/<CODE>.mp4` and `content/<CODE>.srt` (codes are a
   topic‑letter prefix + number, e.g. `FR9`, `AS28`).
2. Add an entry to `data/catalog.json` (`id`, `yt`, `title`, `full_title`, `topic`,
   `topic_label`, `duration_min`, `video`, `transcript`).
3. Add a 1–2 sentence note to `data/notes.json` (this is the AI's Q&A context — keep it
   short so answers stay fast).
4. Add a quiz to `data/quizzes.json` (`questions`: one multiple‑choice, one open‑ended).
5. Add the code→grade mapping in `server.py`'s grade table and a line in
   `app/lesson_codes.txt`.
6. Rebuild the transcript and restart the app:
   ```bash
   cd ~/lightbox && python3 app/prep.py
   systemctl --user restart khan-tutor
   ```

The catalog/notes/quizzes load at startup, so a restart is required after editing them.
See [ARCHITECTURE.md](ARCHITECTURE.md) for how codes, topics, and grades wire together.

## Optional: pre‑build translations

Translating on first view adds a short delay that then caches. To pre‑build everything
(heavy — run when no students are connected):

```bash
cd ~/lightbox/app && nice -n 19 python3 i18n_build.py
```

## Health check cheat‑sheet

```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
systemctl --user status khan-tutor llama libretranslate   # all three running?
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8090/      # app -> 200
curl -s http://127.0.0.1:8080/v1/models                              # model up?
curl -s http://127.0.0.1:5000/languages                             # translate up?
ss -ltnp | grep -E ':8090|:8080|:5000'                              # who owns the ports
```
